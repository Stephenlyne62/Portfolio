Overview

The problem

Restaurant booking products must serve several audiences at once. Customers need a clear way to discover restaurants and manage reservations, while restaurant teams need operational tools for bookings, menus, staff, availability, images, and analytics.

RestBoo brought these workflows into one application while preserving a clear experience for each user type.

Contribution

What I owned

I delivered the complete front end within the project team and translated backend functionality into responsive, role-based user journeys.

  • Customer search, restaurant discovery, detail pages, and booking flows
  • Booking management, cancellation, messaging, and user profiles
  • Restaurant creation, editing, image uploads, gallery management, and staff administration
  • Analytics dashboards, restaurant filtering, KPI cards, and chart visualisations
  • Authentication states, validation, empty states, and API error handling
  • Git-based collaboration and front-end integration with the wider team

Product

Interface gallery

The application covers customer-facing discovery, booking management, restaurant administration, and analytics.

Engineering

Technical approach

The front end was built with Pug templates, JavaScript, jQuery, Mustache.js, Chart.js, and REST APIs.

Mustache.js was used alongside Pug to render dynamic, API-driven content while fitting into the team’s existing architecture. This allowed the application to retain reusable server-rendered layouts while updating interface sections with backend data.

Challenges

Key engineering challenges

Four user roles

Each role required different navigation, permissions, workflows, and interface states without making the application feel fragmented.

API-driven interfaces

The front end needed to handle loading, validation, successful responses, failures, and empty states consistently across many features.

Data visualisation

Booking and restaurant performance data had to remain clear across responsive layouts and different restaurant filters.

Team integration

Front-end delivery depended on ongoing coordination with backend work, endpoint changes, shared branches, and team deadlines.

Outcome

What the project demonstrates

RestBoo demonstrates my ability to take ownership of a substantial front end, collaborate in a multi-developer environment, integrate complex APIs, and turn business requirements into a coherent product experience.

It is my strongest evidence of team-based software delivery and front-end ownership across a product with multiple audiences and interconnected workflows.
