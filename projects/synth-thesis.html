Research Question

Can synthesis be
easier to understand?

Traditional software synthesizers expose sound design through technical concepts such as oscillator shapes, envelopes, filters, modulation and signal routing.

While these controls provide flexibility, novice users may struggle to connect individual parameters with the musical result they are trying to create.

The project investigated whether presenting equivalent functionality through a more educational, goal-oriented interface could improve usability, confidence and understanding.

What I Built

Two interfaces.
One audio engine.

I independently designed and developed two synthesizer interfaces connected to the same underlying C++ sound generation system.

  • Conventional technical synthesizer interface
  • Goal-oriented educational interface
  • Shared object-oriented C++ synthesis engine
  • Oscillator, envelope, filtering and DSP functionality
  • Controlled interface comparison
  • Structured user evaluation

Interfaces

Two approaches to the same system

Both interfaces expose the same synthesis functionality. The interaction model changes while the underlying audio engine remains consistent.

Evaluation

Controlled user testing

Novice users completed equivalent synthesis activities using both interfaces so the interaction approaches could be compared under consistent conditions.

01

Equivalent functionality

Both conditions used the same synthesis engine so the comparison focused on interface design rather than differences in audio capability.

02

Novice perspective

The study focused on users without extensive synthesis experience and how they understood and approached the controls.

03

Comparable activities

Participants followed a consistent process across both interface conditions to support a meaningful comparison.

04

Mixed evidence

Evaluation considered participant performance alongside reported usability, confidence and understanding.

Challenges

Key engineering challenges

The project required both a reliable real-time audio system and a controlled research design in which interface differences could be evaluated meaningfully.

01

Separating interface and audio logic

The software needed a clear boundary between presentation, parameter mapping and real-time audio processing.

02

Functional equivalence

Both interfaces needed comparable capabilities despite presenting synthesis through different interaction models.

03

Real-time DSP behaviour

Audio parameters needed to respond predictably while maintaining stable and continuous sound output.

04

Designing a valid comparison

Unrelated differences between conditions needed to be minimised so interface design remained the central variable.

Outcome

What the project demonstrates

Independent development of a substantial software system combining object-oriented C++, real-time DSP, interface design and human-computer interaction.

The thesis also demonstrates research planning, controlled comparison and user-centred evaluation — treating software development as more than implementation alone.
